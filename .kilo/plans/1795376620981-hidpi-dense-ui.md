# HiDPI rendering + denser UI (crisper, ~15 pt)

## Goal

Render the existing Nuklear UI at native Retina resolution, and scale the whole UI to 80% of its current point size. The OS window stays 900x520 pt. No playback/engine changes.

## Verified context

- SDL 2.32.10 (`/opt/local`). A probe with `SDL_WINDOW_ALLOW_HIGHDPI` on this Mac reports `window=900x520`, `renderer_out=1800x1040` (ratio 2.0). The unbundled binary is already Retina-capable here, so no `Info.plist`/app bundle work is needed (the `SDL_WINDOW_ALLOW_HIGHDPI` header caveat about `NSHighResolutionCapable` does not bite in this setup).
- Nuklear's SDL backend draws in **renderer pixel** coordinates, while SDL mouse events arrive in **window point** coordinates. They must be reconciled.
- Current UI metrics are hard-coded 1x values in `src/main.c`: font 19 px (`main.c:54`), row heights 30/35 (`main.c:132,140,144,150,163`), static widths 90/60 (`main.c:133,164`).
- Built-in font is ProggyClean (`nk_font_atlas_add_default`); windows use Nuklear default style from `nk_style_default`.
- `nk_style_default` / `nk_style_from_table` do not touch `style.font`; safe to re-apply style then set font.
- Adding fonts before `nk_font_atlas_bake` prevents Nuklear's automatic 13 px fallback font.

## Design

- `UI_DENSITY = 0.8f` — uniform 80% of today's design (19 pt -> 15.2 pt).
- `backing_ratio = renderer_output_w / window_point_w` (1.0 or 2.0 on macOS).
- `ui_scale = backing_ratio * UI_DENSITY`.
- Lay out in **physical pixels**: Nuklear window rect is `(0, 0, px_w, px_h)`.
- Pre-bake two font sizes at startup:
  - `font_1x = nk_font_atlas_add_default(atlas, 19.0f * UI_DENSITY * 1.0f, &cfg)` (~15.2 px)
  - `font_2x = nk_font_atlas_add_default(atlas, 19.0f * UI_DENSITY * 2.0f, &cfg)` (~30.4 px)
  - Pick `font_2x` when `backing_ratio >= 1.5f`, else `font_1x`.
- Scale all UI metrics by `ui_scale`; `S = 1.6` (2x) keeps 30/35/90/60 -> 48/56/144/96, and `S = 0.8` (1x) gives 24/28/72/48.
- Mouse coordinates are scaled by `backing_ratio` only (points -> physical pixels), **not** by `ui_scale`.
- Crispness details: request nearest texture filtering before the font texture is created, and enable Nuklear font `pixel_snap`.

## Changes — `src/main.c` (only source file)

1. **Window creation** (`main.c:32-34`): add `SDL_WINDOW_ALLOW_HIGHDPI` to the flags. Keep the 900x520 pt size.

2. **DPI helpers** (new statics near the top of `main` support code):
   - `static int ui_get_pixel_size(SDL_Window *win, SDL_Renderer *ren, int *px_w, int *px_h)` — call `SDL_GetWindowSize` for points and `SDL_GetRendererOutputSize` for pixels; fall back to the point size if output size fails. Return the ratio as `(float)px_w / point_w` (guard divide-by-zero -> 1.0f).
   - `static void ui_scale_style(struct nk_context *ctx, float s)` — multiply the numeric fields below from their default values, rounding with `lroundf`. Caller will call `nk_style_default(ctx)` first so values are not compounded.
   - `static void ui_select_font(struct nk_context *ctx, float ratio, struct nk_font *font_1x, struct nk_font *font_2x)` — choose font by ratio and `nk_style_set_font`.

3. **Font setup** (replace `main.c:50-56`):
   - Call `SDL_SetHint(SDL_HINT_RENDER_SCALE_QUALITY, "0")` (nearest) before `nk_sdl_font_stash_begin`, so the atlas texture created in `nk_sdl_font_stash_end` is crisp at 1:1.
   - Build one `struct nk_font_config cfg = nk_font_config(0); cfg.pixel_snap = 1;` and pass it to both `nk_font_atlas_add_default` calls.
   - Keep `font_1x` / `font_2x` pointers. After `nk_sdl_font_stash_end`, select the font for the startup ratio and call `nk_style_default(ctx); ui_scale_style(ctx, initial_ui_scale); nk_style_set_font(...)`.
   - Do not touch `vendor/nuklear.h` or `vendor/nuklear_sdl_renderer.h`.

4. **Main loop sizing** (`main.c:67,69-86`):
   - Remove reliance on `evt.window.data1/data2` for layout size (those are points).
   - At the top of each frame (or when a resize/display event occurred), call `ui_get_pixel_size` to get `px_w`, `px_h`, `ratio`, and compute `ui_scale`.
   - If `ui_scale` changed since the last frame (compare a cached `float`), re-apply `nk_style_default`, `ui_scale_style(ctx, ui_scale)`, and the font choice. This handles drag between 1x and 2x displays without rebuilding the atlas.
   - Use `nk_rect(0, 0, px_w, px_h)` in `nk_begin`.

5. **Layout constants** (`main.c:127-171`): multiply the numeric metrics by the current `ui_scale`:
   - `30`, `35`, `90`, `60` -> `S(30)`, `S(35)`, `S(90)`, `S(60)` (a small `ui_s(v)` helper or local `float s`).
   - Do not change the widget order or behavior.

6. **Mouse input** (`main.c:84`): add a wrapper that scales event coordinates before `nk_sdl_handle_event`:
   - For `SDL_MOUSEMOTION`: scale `motion.x`, `motion.y`.
   - For `SDL_MOUSEBUTTONDOWN` / `SDL_MOUSEBUTTONUP`: scale `button.x`, `button.y`.
   - Use `lroundf` and the current `ratio`.
   - Leave wheel/keyboard/text/window events untouched.

## Style fields to scale by `ui_scale`

Only the widgets this app uses:

- `ctx->style.window`: `padding`, `spacing`, `border`, `rounding`, `min_row_height_padding`, `scrollbar_size`
- `ctx->style.text`: `padding`
- `ctx->style.button` (and `contextual_button` / `menu_button` if desired): `padding`, `image_padding`, `border`, `rounding`
- `ctx->style.slider`: `border`, `rounding`, `bar_height`, `padding`, `spacing`, `cursor_size`

Round each to whole physical pixels (`lroundf`); preserve zeros. Keep the existing color scheme untouched.

## Validation

1. `make clean && make` — no warnings under `-Wall -Wextra`.
2. `./mediaplayer` on the Retina display — confirm renderer output is 1800x1040 for the 900 pt window, UI text/controls are ~20% smaller than before and visibly sharp.
3. Hit-testing: click `Open`, `Play`, `Pause`, `Stop`, and both sliders, including the far right/bottom edges. Sliders must track the pointer exactly.
4. Resize the window to several sizes; UI fills the window and clicks remain aligned.
5. Force the 1x path: `SDL_VIDEO_HIGHDPI_DISABLED=1 ./mediaplayer` — UI switches to the 15 px font and 1x layout, clicks still aligned.
6. If an external non-Retina display is available, drag the window between displays; layout/font switch live.
7. Regression: load a WAV via CLI, play/pause/stop/seek, quit with Esc. No SDL warnings; audio unaffected.
8. Optional: capture a screenshot at 100% and inspect glyph edges for blur.

## Risks / mitigations

- **Fractional layout coordinates** can soften text: nearest filtering + `pixel_snap`; chosen density keeps 30/35/90/60 integral at both 1x and 2x.
- **Mouse mismatch**: scale input by `backing_ratio`, layout by `ui_scale`; test edges.
- **Style compounding on monitor change**: always `nk_style_default` before reapplying the scaled metrics.
- **Font lost after style reset**: `nk_style_from_table` does not touch `style.font`, but still call `nk_style_set_font` after scaling for clarity.
- **Renderer output query failure**: fall back to window point size (ratio 1.0).
- **No vendor edits**: input scaling and DPI logic stay in `main.c`.

## Out of scope

- App bundle / `Info.plist` (verified unnecessary here).
- Changing the font family.
- Changing the 900x520 pt window size.
- Playback engine work or other PRD phases. Optionally add a one-line bullet to Phase 6 in `docs/PRD.md` noting native HiDPI rendering.
